# CudaAlgorithms

Учебный репозиторий на CUDA C++ для изучения архитектуры GPU, параллельных алгоритмов и практик, полезных Render Programmer.

Все кейсы находятся в одном Git-репозитории и подключаются к общей Visual Studio solution. Каждый кейс — отдельный проект Visual Studio (`.vcxproj`). Реализации и эксперименты выполняются автором; описания проектов фиксируют задачу, подход к проверке и методику измерений.

## Сборка

Откройте `CudaAlgorithms.slnx` в Visual Studio 2026. В Solution Explorer выберите нужный проект как Startup Project, затем конфигурацию `x64` и `Debug` или `Release`.

Для сборки необходимы Visual Studio 2026 с workload **Desktop development with C++**, NVIDIA CUDA Toolkit с интеграцией для Visual Studio и совместимый драйвер. Проекты используют Visual Studio CUDA build customizations и не требуют CMake.

`VectorAdd` сейчас настроен для Toolkit 13.5 и архитектуры `compute_86,sm_86` (NVIDIA Ampere, например GeForce RTX 3070 Ti). Для другой видеокарты проверьте и измените **CUDA C/C++ → Device → Code Generation** в свойствах проекта.

## Измерения CPU и GPU

`Common/Benchmark.h` содержит общий helper для прогрева и серии измерений. Он выводит медианное, минимальное и среднее время. `VectorAdd` сравнивает CPU-эталон с полным GPU-вызовом на массивах разных размеров.

GPU-замер включает выделение и освобождение device-памяти, копирование входов на GPU, запуск и синхронизацию kernel, а также копирование результата обратно. CPU-замер включает вычисление над уже подготовленными массивами. Поэтому сравнение показывает стоимость текущего end-to-end решения, а не только производительность kernel. Для маленьких массивов накладные расходы передачи и запуска могут сделать GPU-вариант медленнее.

Любые результаты производительности следует публиковать вместе с моделью GPU, версией драйвера и Toolkit, конфигурацией сборки, размерами входа и описанием того, что именно включено в замер. Результаты относятся к указанной конфигурации и не являются универсальными.

## Критерии учебных проектов

Каждый кейс должен описывать задачу и ограничения, содержать способ проверки корректности и граничных случаев, фиксировать методику измерений и подводить выводы по результатам. Когда применимо, полезно сравнивать GPU-решение с CPU-эталоном и объяснять влияние передач данных, запуска kernel и использования ресурсов GPU.
